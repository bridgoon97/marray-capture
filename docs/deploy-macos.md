# macOS 部署与使用

> 这台机器是**开发与排练**环境：代码在这里写的、验证过，但受声卡通道数限制，
> 正式采集要去 Windows（见 [deploy-windows.md](deploy-windows.md)）。

---

## 1. 一个必须先知道的限制

`marray-capture --check` 在本机列出的输入设备里，**Scarlett 2i2 只有 2 个输入通道**。
本工具的目标配置是 3 麦 + 1 路 VPU = 4 通道，2i2 装不下。

所以在 macOS 上可以做的是：

- 跑通全流程、验证方案与语音导播
- 用 1–2 个麦克风做**单/双通道排练**（把通道映射里只留 2 路 `mic`，
  后处理页的阵列几何相应改成 `linear` / 2 麦）
- 后处理、质检、增强这些不碰声卡的部分，完全可用

真正的 4 通道采集需要一块 ≥4 输入的接口（或用「聚合设备」把两块 2i2 拼起来，
见下文 §6），否则请直接在 Windows 上做。

## 2. 安装

### 方式 A：uv（推荐，和 Windows 保持一致）

```bash
brew install uv          # 或 curl -LsSf https://astral.sh/uv/install.sh | sh
cd ~/Projects/marray-capture
uv sync --extra tts      # 只要基础功能可以省掉 --extra tts
uv run marray-capture --check
uv run marray-capture
```

`uv sync` 会自己准备好合适的 Python，不需要预先装。

### 方式 B：已有的 .venv

仓库里已经有一个我用来验证的 `.venv`（gitignore 掉了，不会进仓库）：

```bash
cd ~/Projects/marray-capture
.venv/bin/python -m marray_capture --check
.venv/bin/python -m marray_capture
.venv/bin/python -m pytest -q          # 24 个用例，不需要声卡、不联网
```

两种方式二选一即可，不要混着用。

## 3. 麦克风权限（最容易踩的坑）

macOS 的 TCC 权限是按**发起进程**授予的。第一次录音时系统会弹窗；如果没弹或
误点了拒绝，录出来的是**一整段数字零**——软件的质检会报「几乎没有信号，疑似死麦」。

打开 **系统设置 → 隐私与安全性 → 麦克风**，确认给了权限：

- 用终端启动 → 授权对象是 **终端 / iTerm**
- 用 IDE 启动 → 授权对象是那个 IDE

改完权限要**完全退出并重开**那个 App（`Cmd+Q`，不是关窗口），否则不生效。

## 4. 蓝牙音箱：别让它变成输入设备

macOS 上蓝牙音频有两套模式：

| 模式 | 何时启用 | 采样率 | 能用吗 |
|---|---|---|---|
| **A2DP**（立体声） | 只把 BT 设备当**输出** | 44.1 / 48 kHz | ✅ 就要这个 |
| **HFP**（免提） | BT 设备**同时被当作输入** | 8 / 16 kHz 单声道 | ❌ 灾难 |

一旦 macOS 认为你在用蓝牙设备的麦克风，整条链路会掉到 HFP，扫频信号的高频
直接没了。**保证「输入设备」永远选 USB 声卡，绝不要选蓝牙设备。**

判断方法：在设备页点「① 播放测试音」，5 个音（250/500/1k/2k/4k Hz）都应该清晰；
如果听起来闷、像打电话，那就是掉到 HFP 了。去 系统设置 → 声音 → 输入，
把输入切回 USB 声卡，再重连蓝牙。

> 有条件的话，把音箱用线接到声卡输出，这一整节的问题都不存在，IR 质量也更好。

## 5. 语音导播

piper 的中文模型已经下载在本机：

```
~/.marray-capture/piper/zh_CN-huayan-medium.onnx        (63 MB)
~/.marray-capture/piper/zh_CN-huayan-medium.onnx.json
```

预渲染的提示音缓存在 `~/.marray-capture/prompt_cache/`，跨会话共享。

macOS 上四个后端都可用（`--check` 验证过）：piper / edge-tts / SAPI 等价物
（pyttsx3 走 NSSpeechSynthesizer）/ `say`。自动选择的结果是 **piper**。

想换成音质更好的 edge-tts：方案页把「后端」切到 `edge-tts`，点「试听一句」确认，
再「预渲染语音」。预渲染完就不再需要网络。

## 6. 想在 Mac 上凑够 4 通道：聚合设备

`应用程序 → 实用工具 → 音频 MIDI 设置`：

1. 左下角 `+` → 创建聚合设备
2. 勾选两块接口，**给其中一块勾上「漂移校正」**（不勾会累积时钟漂移）
3. 记下子设备的顺序——聚合设备的通道号就是按这个顺序拼接的

然后在设备页选这个聚合设备，通道映射按实际接线填。

⚠️ 聚合设备的两块接口时钟不同源，即使有漂移校正也会引入抖动，会直接体现在
质检的「时间弥散」和「两次扫频一致性」上。**这是排练手段，不是正式采集方案。**

---

## 7. 排练流程（约 15 分钟）

1. 设备页：输入选 USB 声卡，输出选音箱；通道映射按实际接线填
2. ① 播放测试音 → 音箱有声，且不闷
3. ② 电平检查 10 秒 → 无死麦、通道间电平差 < 12 dB、不削顶
4. ③ 环境底噪 30 秒
5. ④ 延迟标定 → 记下往返延迟和漂移 ppm
6. 方案页：把「距离」「音箱高度」都只填一个值，格数改成 3，随机位改成 1，
   重戴改成 0 —— 生成一个 5 分钟的迷你方案
7. 试听一句 → 预渲染语音
8. 采集页：开始，跟着语音走一遍
9. 质检页：看全部 PASS 没有；后处理页跑一次增强

这一轮能把「权限、蓝牙模式、电平、语音音量、指令听不听得懂」全部暴露出来。
**正式采集前一定要在目标房间做一次**，哪怕在 Windows 上重做也不亏。
