# Windows 部署与使用

> 这是**正式采集**环境。下面按「装 → 配 → 试 → 采」的顺序写，
> §3 的 Host API 和 §4 的蓝牙是两个最容易翻车的地方，别跳过。

---

## 1. 安装

```powershell
# 装 uv（只需一次）。装完关掉再重开 PowerShell，让 PATH 生效
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

git clone https://github.com/bridgoon97/marray-capture.git
cd marray-capture

uv sync --extra tts      # 带开源 TTS；不要语音导播可以省掉 --extra tts
uv run marray-capture --check
```

不需要预先装 Python，`uv sync` 会自己下一个合适的版本。

**路径别带中文和空格。** 放 `C:\Projects\marray-capture` 这类位置最省事。

如果 `--extra tts` 里的 `piper-tts` 装不上（onnxruntime 对 Python 版本挑剔），
退而求其次：

```powershell
uv sync --extra edge     # 只装 edge-tts，预渲染时联网即可
uv sync                  # 什么都不装，降级为提示音 + 屏幕大字，流程照样跑
```

启动：

```powershell
uv run marray-capture
```

## 2. 先跑 `--check`

它会列出所有输入/输出设备（含 Host API）和四个 TTS 后端的可用性。
**接线问题、通道数不够、缺中文语音，全部在这一步暴露。**

---

## 3. Host API：Windows 上最关键的一个选择

PortAudio 在 Windows 上会把**同一块声卡重复列好几遍**，每遍对应一个 Host API。
设备页的下拉里能看到形如 `[3] Scarlett 4i4 (MME, in 2 / out 2)`、
`[11] Scarlett 4i4 (Windows WASAPI, in 4 / out 4)` 这样的条目。

| Host API | 多通道 | 延迟 | 建议 |
|---|---|---|---|
| **WASAPI** | ✅ 全通道 | 低 | **首选**（ASIO 条目多半根本不会出现，见下节） |
| WDM-KS | ✅ | 最低 | 可用，但独占设备、兼容性差 |
| MME | ❌ 常被截到 2 通道 | 很高 | **不要用**（但它是默认，容易误选） |
| DirectSound | ❌ 同上 | 高 | 不要用 |
| ASIO | ✅ | 最低 | 标准 sounddevice 轮子里**没有**，见下节 |

**选设备时看清楚括号里的 Host API 和输入通道数。** 如果输入通道数只有 2，
说明你选到 MME 那一条了。

### 看不到 ASIO 条目？这是正常的

**PyPI 上的 `sounddevice` 轮子自带的 PortAudio 没有编译 ASIO 支持**（ASIO SDK 有
授权限制）。所以即使你装了 ASIO4ALL，设备列表里也只会有 WASAPI / MME /
DirectSound / WDM-KS，**不会出现 ASIO 条目**。这不是配置问题。

**结论：Windows 上就用 WASAPI。** 它同样能拿到全部输入通道，延迟也够低，
而且不像 ASIO 那样独占设备。软件对 ASIO 的支持（全双工单流）保留着，
只有在你自行替换了带 ASIO 的 PortAudio DLL 时才会用到。

### WASAPI 的通道数限制（会遇到的第一个报错）

WASAPI 共享模式**只接受端点混音格式的完整通道数**。8 通道的卡上如果只请求
5 个通道，会直接报 `Invalid number of channels`。

软件已经自动处理：先按用到的最大通道号试，被拒就退到声卡的完整通道数打开，
再按通道表切片。第一次回退后会记住，之后不再试错，日志里会有一句提示。
多录的几路只是占点磁盘，不影响结果。

### 选设备

1. 输入设备 = USB 声卡的 **Windows WASAPI** 条目（看括号里的输入通道数是不是全的）
2. 输出设备 = 音箱的端点（蓝牙见 §4）
3. 「收发模式」保持「自动」

如果音箱是接在同一块声卡输出上的，输入输出选同一个设备，软件会自动走
**全双工单流** —— 收发采样锁定，**没有时钟漂移**，延迟就是设备往返延迟。
质检里的「时钟漂移 ppm」会稳定在 0 附近，比蓝牙那条路干净得多。

## 3.5 通道映射：接线顺序不用迁就软件

麦克风接在声卡的哪几个通道上完全随意。通道表三件事分开管：

| 列 | 作用 |
|---|---|
| **录制** | 勾了才录。没勾的通道软件完全不碰 |
| **用途** | 点一下换一个：麦克风 → VPU → 参考麦 |
| **麦序号** | 只对麦克风有效。它是第几个麦克风 |

**麦序号决定 IR 里的麦克风顺序，物理通道号不决定。** 举个真实例子：

| 麦序号 | 声卡通道 |
|---|---|
| mic1 | ch6 |
| mic2 | ch3 |
| mic3 | ch2 |
| mic4 | ch5 |
| VPU | ch7 |

摘要行会显示：

```
IR 通道顺序：1:mic1、2:mic2、3:mic3、4:mic4、5:vpu
对应声卡通道：ch6、ch3、ch2、ch5、ch7（会向声卡请求 7 个通道再切片）
⚠ 后处理页的阵列几何必须配成 4 个麦克风，且坐标第 k 行要对应上面的第 k 个麦克风
```

**开录前一定要核对这两行。** 麦序号填错不会报错，只会让后处理时的阵列几何和
实际麦克风对错位 —— 这是整条链路里唯一会静默出错的地方。

8 通道卡逐行点太慢的话，上面的「前 N 路作麦克风 + 其后一路作 VPU + 套用」
可以先铺一个起点，再挪勾选和麦序号。

不确定哪个物理通道是哪只麦克风？用「② 电平检查」：录 10 秒，逐只麦克风说话，
看电平表哪一路在动。

## 4. 蓝牙音箱：一定要选「立体声」端点

Windows 会把一个蓝牙音频设备拆成两个端点：

| 端点名 | 协议 | 采样率 | 能用吗 |
|---|---|---|---|
| `xxx (Stereo)` / `立体声` | A2DP | 44.1 / 48 kHz | ✅ 就要这个 |
| `xxx (Hands-Free)` / `免提电话` | HFP | 8 / 16 kHz 单声道 | ❌ 高频全没 |

输出设备下拉里两个都会出现，**必须选 Stereo 那个**。

另外：

- **绝不要把蓝牙设备选成输入。** 一旦 Windows 认为你在用它的麦克风，
  会强制整条链路切到 HFP，Stereo 端点同时失效。
- 采集期间不要接微信/腾讯会议这类会抢占通信设备的软件，它们会把蓝牙切到 HFP。
- 设备页点「① 播放测试音」，5 个音（250/500/1k/2k/4k Hz）都该清晰；
  听起来像打电话就是掉到 HFP 了。

> 蓝牙的有损编码（SBC/AAC）会在 IR 上留一层宽带噪底 —— 它不是谐波失真，
> 不会被 ESS 推到负时间。**能用线接到声卡输出就用线**，质量差别是实打实的。
> 质检的「可靠带宽」指标会告诉你实际损失了多少高频。

## 5. 系统设置

### 麦克风隐私权限

`设置 → 隐私和安全性 → 麦克风` → 打开「让桌面应用访问你的麦克风」。
没开的话录到的是一整段零，质检会报「几乎没有信号，疑似死麦」。

### 采样率对齐

`控制面板 → 声音 → 录制 / 播放 → 属性 → 高级`，把 USB 声卡和音箱端点的
默认格式都设成 **48000 Hz**，和软件里的采集采样率一致。WASAPI 共享模式下
两边不一致会开流失败或被系统偷偷重采样。

### 电源管理（一场采集要跑 40 分钟以上，别让它掉线）

- `电源和睡眠` → 屏幕和睡眠都设为「从不」
- 电源模式 → 「最佳性能」
- `设备管理器 → 通用串行总线控制器 → USB Root Hub → 属性 → 电源管理`
  → **取消勾选**「允许计算机关闭此设备以节约电源」（每个 Root Hub 都要）
- 高级电源设置 → USB 设置 → **USB 选择性暂停 = 已禁用**

### SmartScreen

第一次跑 uv 的安装脚本可能被 SmartScreen 拦，点「更多信息 → 仍要运行」。

## 6. 从 macOS 迁移过来的东西

| 东西 | 怎么办 |
|---|---|
| 代码 | `git clone`，不要拷贝目录 |
| `settings.json` | **不要直接拷。** 里面存的是设备**索引**，跨机器毫无意义，会指到错的声卡上。重新配一遍设备页即可，其余参数在方案页填 |
| piper 中文模型 | 重新点「下载中文语音模型」最省事；想省流量可以把 `~/.marray-capture/piper/` 整个拷到 `%USERPROFILE%\.marray-capture\piper\` |
| 提示音缓存 | 不用拷，重新预渲染只要十几秒 |
| 采集方案 | 方案页「保存方案」出的 `plan.json` 是纯数据，可以跨机器用「载入方案」 |

## 7. 磁盘空间

默认参数（48 kHz / 4 通道 / 每位置 2 次 5 秒扫频 / 保存原始录音）下：

- 单个位置的原始录音 ≈ **8–11 MB**（FLAC / 24-bit）
- 单个位置的 IR ≈ 0.8 MB（48k）+ 0.26 MB（16k）
- 一轮完整协议 120 个位置 ≈ **1.2 GB**
- 本人 + 3 位协助者 + 补录 ≈ **6 GB**，增强产物另算

**预留 20 GB**。空间紧张时可以在方案页关掉「保存原始录音」，但不建议 ——
出了问题没法重新提取。

## 8. 开录前的固定动作

1. **设备页**
   - 输入 = USB 声卡的 **Windows WASAPI** 条目（不要选 MME）
   - 输出 = 音箱端点；蓝牙的话选 **Stereo**，接在同一块声卡上的话选同一个设备
   - 通道映射（见 §3.5）：勾选要录的通道 → 点「用途」切成麦克风/VPU/参考麦 →
     填「麦序号」。核对摘要行的「IR 通道顺序 ↔ 对应声卡通道」
   - 采样率 48000
2. **① 播放测试音** → 音箱有声、不闷
3. **② 电平检查 10 秒**（对着麦说话）→ 无死麦、通道间电平差 < 12 dB、峰值不过 −6 dBFS
4. **③ 环境底噪 30 秒** → 记录本场噪声基线
5. **④ 延迟标定** → 记下往返延迟和漂移 ppm。
   漂移 > 200 ppm 就别用蓝牙了，换有线
6. **方案页** → 填被试/佩戴编号 → 生成方案 → 选 TTS 后端 → **试听一句**（确认
   佩戴者在 2 米外能听清）→ **预渲染语音**
7. **采集页** → 开始

---

## 9. 采集中

- 佩戴者听语音指令行动，倒计时**最后一声是升调**，听到就别动了
- 采完一个位置有反馈音：**上行两声 = 过**，**下行两声 = 没过**（会自动重录一次）
- 操作者盯着采集页右侧的 QC 表；出现连续 FAIL 就按「暂停」查原因
- 中途要改姿势/休息：按「暂停」，回来按「继续」
- 某个位置明显录坏了：按「重录当前位置」

---

## 10. 采完立刻做（**不要留到回去**）

**质检页** → 选本次会话 → 看顶部的分组统计。

它会标出「批量失败的分组」，比如 `grid/W1/50cm: 6/8 FAIL`。
**整组失败说明是系统性问题**（某个距离电平不够、某次佩戴松了、蓝牙重连了），
当场补录成本极低，人走了就补不回来了。

补录：在表里选中要重来的行 → 「把选中的位置加入补录」→ 自动切到采集页只跑这些位置。

---

## 11. 后处理

**后处理页**：

1. 选会话，采样率选 16000（训练管线用的）
2. 质检门槛选「只用 PASS」（数据不够时可放宽到 PASS + WARN）
3. 有音箱参考 IR 的话：选上 → 「设计反滤波器并预览」→ 勾「增强前先去音箱响应」
4. **阵列几何必须和实物一致**。3 麦 1 cm 等边三角形有预设；**4 麦或其它布局选
   「自定义坐标」**，每行填一个麦克风的 `x, y, z`（单位米）。例如 4 麦 1 cm 正方形：

   ```
   0.005,  0.005, 0
   0.005, -0.005, 0
   -0.005, -0.005, 0
   -0.005,  0.005, 0
   ```

   摘要行会回显「N 个麦克风，最大间距 … cm」，核对一下。
   晚期尾的通道间相干性 `sinc(2πf·d/c)` 完全由这个几何决定 —— **填错会让下游
   波束形成器得到过于乐观的结果**，是这一步唯一会静默出错的地方。
   会话里的实际麦克风数和几何对不上时，日志里会直接提示。
5. 「开始增强」

输出在 `<会话>/aug/`，附 `manifest.jsonl` 记录每条采样到的 T60 / DRR / 尾长等参数，
可复现、可按参数筛选。

## 12. 常见故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 输入通道数只有 2 | 选到 MME 条目了 | 换 ASIO / WASAPI 条目 |
| 开流报「Invalid number of channels」 | WASAPI 只收完整通道数 | 软件会自动退到全通道数重开；若仍失败，把系统里的声卡格式改成 48 kHz |
| 设备列表里没有 ASIO | 标准 sounddevice 轮子不带 ASIO | 正常现象，用 WASAPI |
| 开流报「Device unavailable」 | ASIO 设备被开了两条流 | 输入输出选同一个 ASIO 条目，收发模式设「自动」或「强制全双工」 |
| 增强报「麦克风通道数和几何对不上」 | 阵列几何还是 3 麦预设 | 后处理页改「自定义坐标」，按实物填坐标 |
| 所有通道「几乎没有信号」 | 麦克风隐私权限没开 | §5 |
| 测试音听起来像打电话 | 蓝牙掉到 HFP | §4，确认输入不是蓝牙设备 |
| 开流报「不支持的采样率」 | 系统端点和软件不一致 | §5 采样率对齐；或用 WASAPI |
| 漂移 ppm 很大、时间弥散变宽 | 蓝牙链路在重同步 | 换有线；或把音箱接到同一块声卡 |
| 一致性 NCC 掉到 0.9 以下 | 佩戴者在两次扫频之间动了 | 提醒别动；必要时把 settle 时间调长 |
| 可靠带宽只到 4–5 kHz | 蓝牙编码劣化 / 音量太小 | 提高播放幅度；换有线 |
| 采集中途出现 xrun 告警 | USB 省电 / 系统抢占 | §5 电源管理；输出延迟模式设 `high` |
| 语音导播没声音 | TTS 没装或模型没下 | `--check` 看后端状态；点「下载中文语音模型」 |

## 13. 参数速查（默认值）

| 参数 | 默认 | 说明 |
|---|---|---|
| 采样率 | 48000 | 同时导出 16k 给训练管线 |
| 扫频 | 40 Hz → 20 kHz，5 s | 自动夹到 0.98×Nyquist |
| 每位置扫几次 | 2 | ≥2 才有一致性质检 |
| 扫频前静音 | 1.5 s | 同时是质检的噪声窗 |
| 最大延迟余量 | 1.0 s | 蓝牙延迟大时调大 |
| IR 长度 | 1000 ms | 直达峰前保留 5 ms |
| 早/晚分界 | 50 ms | 早期段保留实测，晚期尾随机合成 |
| T60 / DRR | 0.2–0.8 s / 0–15 dB | 增强时随机采样 |

完整协议默认 138 步、120 个测量位，预计 **58 分钟**（方案页会实时算给你看）。
