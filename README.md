# marray-capture

开放式耳机麦克风阵列 —— **干扰人扫频实录**采集工具。一个 GUI 串起五步：

```
1 设备  →  2 方案  →  3 采集  →  4 质检  →  5 后处理
声卡与    生成粗方向   语音导播    逐位置 IR   去音箱响应 +
通道映射   采集协议     自动跑      可靠性验证   混响随机增强
```

配套的方法论笔记（探针法、sim-to-real 教训、混响增强管线）在作者的私有知识库里，
本仓库只包含工具本身与其设计理由。

## 快速开始（Windows）

```powershell
# 装 uv (只需一次)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

cd marray-capture
uv sync --extra tts              # 带开源 TTS；只要基本功能可以省掉 --extra tts
uv run marray-capture            # 启动 GUI
uv run marray-capture --check    # 环境自检: 列出声卡设备与可用 TTS 后端
uv run pytest                    # 跑自检用例 (不需要声卡、不联网)
```

先跑 `--check`。它会把系统识别到的输入/输出设备和四个 TTS 后端的可用性都列出来，
接线有问题或缺中文语音在这一步就能看见。

## 语音导播

采集时佩戴者在房间里、手够不到电脑，指令靠音箱播报。指令文本在「方案」页
**预渲染并缓存**，采集过程中不跑 TTS，所以现场断网也照跑。默认协议 138 步里
只有 44 条不重复的指令，合成一次几秒钟。

四个后端按优先级自动选：

| 后端 | 开源 | 联网 | 中文音质 | 安装 |
|---|---|---|---|---|
| **piper** | 是（MIT） | 只在下载模型时 | 好 | `uv sync --extra piper`，再点界面上的「下载中文语音模型」（约 63 MB） |
| **edge-tts** | 客户端开源，服务是微软的 | 预渲染时要联网 | 最好 | `uv sync --extra edge` |
| SAPI | 否 | 否 | 取决于系统语音包 | Windows 自带，缺中文包就不可用 |
| say | 否 | 否 | — | macOS 开发调试用 |

**默认建议 piper** —— 真·开源、纯离线、装完就不再依赖任何外部服务。想要更自然的
播报腔可以切 edge-tts，反正只在准备阶段联网。全都不可用时自动降级为提示音编码
+ 界面大字，流程不中断。

缓存是跨会话共享的（`~/.marray-capture/prompt_cache`，键含后端与语音），换人换场次
不必重新合成。「预渲染语音」还会把音频连同文本索引导出一份到 `<会话>/prompts/`，
开录前可以逐条试听核对。

提示语走**和扫频同一个输出设备**（音箱）—— 佩戴者戴着待测耳机，不能用耳机放提示音，
否则会被自己的麦克风录进去。提示语只在稳定期之前播，扫频窗内是纯静音。

## 设计要点

### 两种收发模式

| 模式 | 何时用 | 时钟 |
|---|---|---|
| **全双工单流** | 输入输出是同一台设备（ASIO4ALL、或音箱接在声卡输出上） | 采样锁定，**无漂移** |
| **分离双流** | 输入输出是两台设备（USB 声卡 + 蓝牙音箱） | 不同源，逐位置估计漂移 |

默认「自动」：同设备走全双工。**ASIO 必须走全双工** —— 绝大多数 ASIO 驱动
（含 ASIO4ALL）单实例独占，一块设备开两条流会直接失败。

两种模式下播放缓冲区布局一致（`[guard 静音][play][tail 静音]`，录音从 0 开始），
所以上层的峰值定位逻辑不用区分模式。软件**不依赖任何流间时序**：每次扫频的位置
都在反卷积域按峰值定位。

跨设备（蓝牙）路线的代价与对策：

| 问题 | 对策 |
|---|---|
| 蓝牙延迟大且每次不同（可达数百毫秒） | 「延迟标定」测一次；搜索窗默认给 1 秒余量 |
| 两端时钟漂移，IR 被时间弥散 | 每个位置估 ppm 并质检报警；可选按 ppm 重采样补偿 |
| SBC/AAC 是有损编码，会在 IR 上留宽带噪底 | 每位置扫 2 次求平均；一致性指标会直接暴露劣化 |

> 有条件的话，把音箱接到同一块声卡的输出上，以上三条全部消失 —— 软件会自动切成
> 全双工，质量明显更好。

### 通道数是任意的

输入通道映射表按声卡实际通道数生成，逐路指定用途（`mic` / `vpu` / `ref` /
`loopback` / `ignore`）。8 通道卡上挂 4 麦 + VPU 没问题，麦克风也不必从 1 号开始。
录制时录到所选最大通道号为止，再按表切片；切片后的顺序就是 IR 文件里的通道顺序。

麦克风数不是 3 时，**后处理页的阵列几何要改成「自定义坐标」**并按实物逐行填
`x, y, z`（单位米）。晚期尾的通道间相干性 `sinc(2πf·d/c)` 完全由这个几何决定，
填错会让下游波束形成器得到过于乐观的结果 —— 软件会在会话通道数与几何不符时提示。

### 采集协议不需要角度标定

方位维度全部用「向右转一格」表达 —— 佩戴者坐转椅上原地转即可，每转四分之一圈
播一句粗方向校验（"音箱现在应该大致在你的正左方向"）防止累计误差。
角度标签只是名义值，**只用于分组统计，不参与任何计算**。

循环顺序按操作成本排：高度（走到支架旁）> 距离（挪椅子）> 方位（转椅子）。
音箱朝向是**圈级**参数——音箱固定指向椅子时，佩戴者原地旋转不改变相对朝向，
所以「干扰人没正对你」只能整圈重来一次，每种朝向只需走过去调一次。

### 每个位置只发起一次播放/录音

播放缓冲区布局：

```
[语音指令][停顿][位置编号提示音][倒计时][preroll 静音][扫频][gap][扫频][tail 静音]
                                              ^ 噪声窗       ^ 信号窗
```

指令、编号音、扫频在同一个录音文件里，事后可追溯；指令与扫频之间没有流启停间隙。
编号提示音把位置序号编成短音串，manifest 和音频万一对不上可以从音频里读回来。

### 质检指标

| 指标 | 抓什么 |
|---|---|
| 峰值 dBFS | 削顶、死麦、接线错 |
| 录音 SNR | 环境太吵、音箱音量不够 |
| IR 直达噪底比 (DDR) | 反卷积后的有效动态范围 |
| 可靠带宽 | 哪个频率以上已经埋进噪声（分倍频带算） |
| **两次扫频一致性 (NCC)** | 佩戴者动了、蓝牙重同步、编码劣化 —— 最有用的一个 |
| 两次扫频电平差 | 同上 |
| 时钟漂移 ppm | 两台设备不同源的程度 |
| 时间弥散 ms | 直达峰 -10dB 宽度，漂移/编码劣化会让它变宽 |

噪声估计取**直达峰之前**的一段：ESS 的谐波失真产物落在 `-L·ln(k)` 处
（`L = T/ln(f2/f1)`），二次谐波之后到直达峰之间那段既没有失真产物也没有混响，
是干净的反卷积域噪底。用峰后尾巴估会把真实混响算成噪声，偏悲观。

一致性不过时会**自动放弃多次平均**回退到单次 IR —— 亚样本错位下直接平均会梳状衰减高频。

质检页的分组统计会标出「批量失败的分组」，现场就能决定补录哪一圈。

### 后处理

**去音箱响应（可选）**：用测量麦在音箱正轴 1 米录一条参考 IR，取前 20 ms（避开房间反射）
估幅度、1/3 倍频程平滑、限幅提升量、做成最小相位 FIR。做 RTF（麦间相对量）时音箱响应
是公共项会自己约掉，但把 IR 直接卷积干净语音生成训练音频时不会，所以正式数据建议做。

**混响随机增强**：vendored 自 `rir-augment`，保留实测早期段（直达+早期反射，承载阵列/
近场/头部线索），按随机 T60/DRR 重新合成带正确通道间相干性 `sinc(2πf·d/c)` 的晚期尾。
与原版的两点差异：

1. **只对麦克风通道合成扩散尾。** VPU 这类非声学通道拾到的是骨导/接触振动，
   套球面各向同性相干模型是错的，保留实测原样。
2. **按质检结论筛输入**，FAIL 的位置不进增强。

## 会话目录

```
<会话根目录>/<会话名>/
    session.json      配置快照
    plan.json         采集方案
    manifest.jsonl    每位置一行: 元数据 + QC 指标 + 文件名
    qc.csv            质检汇总（扁平表，现场看）
    raw/              原始多通道录音（FLAC/PCM_24，可关）
    ir48k/            提取出的 IR（采集采样率，float32，不做峰值归一）
    ir16k/            重采样到训练管线采样率的 IR
    noise/            环境底噪录音
    prompts/          TTS 缓存
    aug/              增强产物
```

IR 一律存 32-bit float 且**不做峰值归一** —— 通道间与位置间的绝对电平关系是后面算
ILD / DRR 的依据。

## 开录前的固定动作

1. 「设备」页把通道用途配好（mic 进阵列 / vpu 单独存 / ref 是测量麦）
2. ① 播放测试音 → 确认音箱有声
3. ② 电平检查 10 秒 → 看有没有死麦、通道间电平差是否 < 12 dB、会不会削顶
4. ③ 环境底噪 30 秒 → 本场噪声基线
5. ④ 延迟标定 → 收窄搜索窗，顺便看漂移 ppm
6. 「方案」页生成方案 → 选 TTS 后端 → 试听一句确认音量 → 预渲染语音
7. 开录

## 第三方与 vendored 代码

- `src/marray_capture/rir/rir_augment/` 是作者自己的 `rir-augment` 项目的内嵌副本
  （扩散场相干性、晚期尾合成、早/晚分解），改动见上一节的两点差异。
- TTS 后端只是适配层：[piper](https://github.com/OHF-Voice/piper1-gpl)（MIT）与
  [edge-tts](https://github.com/rany2/edge-tts)（GPL-3.0）都是可选依赖，不随本仓库分发。

## 已知限制

- 音箱不是人嘴，没有真实的嘴部指向性。软件提供「音箱朝向」维度作为一阶近似，
  理想方案仍是人工嘴/HATS。
- 晚期尾用球面各向同性相干；阵列贴头时实际扩散场受头部遮挡并非严格各向同性，作一阶近似。
- 蓝牙链路下 IR 的高频段质量受编码器影响，`--check` 和质检的可靠带宽指标会告诉你实际能用到多少 Hz。
